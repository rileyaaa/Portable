## Codex 与 Host 成对更新

当前官方完整 ZIP、版本、目标架构、文件布局和安装后 SHA-256 统一记录在 [runtime-manifest.json](runtime-manifest.json)，不在多个 Markdown 中重复维护哈希。

Codex 对应版本的 [LICENSE](licenses/codex/LICENSE) 和 [NOTICE](licenses/codex/NOTICE) 随包保留，取自官方 `rust-v0.166.0` 标签的同名文件；升级时同步核对上游许可通知，不改写其内容。

1. 正常退出 Codex、Host 和相关工具。在包内 `tmp` 下建立本次更新的独立目录，下载同一稳定 release 的 Windows x64 完整工件，核对官方摘要；保留旧版本的受控恢复副本。
2. 按该版本布局准备主程序、Host、根目录沙箱 helper、`codex-path`、资源目录及适用许可证。本项目只使用文字与 Agent，省略语音目录和已确认与根助手相同的两份资源副本，分别记录在 manifest 的 `excluded_components`；升级时重新核对查找顺序，不能照搬裁减规则。当前主 EXE 命名为 `codex.exe`，仅适配 `codex-package.json` 的 `entrypoint`，删除不使用的独立执行器及 `execServer` 字段（上游 npm 包同样省略），不修改官方 EXE/DLL 字节。
3. 成对替换并同步 `run-codex.ps1` 的固定版本/摘要、manifest 摘要、`login-json.ps1` 的版本映射及四份模式副本。启动前验证 manifest 本身及所列全部文件，不能只更新 EXE。资源目录中的 Host 会优先参与官方解析，若存在，也必须与固定 Host 一致并列入清单。
4. 复核上游配置 schema、feature 和工具调用行为，确认项目环境变量仍被实际消费；更新使用说明和开发记录。
5. 运行下面的发行包检查，再按开发文档完成 Windows 启动、Code Mode 工具调用和相关回归。身份不匹配时恢复完整匹配版本，不关闭校验或 Code Mode。

在包根验证已安装工件：

```powershell
.\tool\python\python.exe -B -m unittest discover -s tests -p 'test_runtime_package.py' -v
.\codex.exe --version
```

每次升级还需核对实际请求协议，尤其内置模型 `use_responses_lite` 等字段不能直接假定自定义 API 兼容；自定义 provider 当前固定标准 Responses。每次升级还需在真实终端验证交互界面及 resume/fork；0.166.0 使用 `--no-daemon` 保持状态在包内。版本号和配置读取成功不能代替交互启动。

测试检查 manifest 所列文件、所有原生助手的 x64 架构、版本映射及文字/Agent 组件范围；它不能代替 Windows 实际启动。当前仓库没有自动 Codex updater；普通使用者可重新解压经过验证的项目发行包，维护者按上述流程更新工作树。

各 EXE 用途见 [README](../README.md#codex-的几个-exe-分别做什么)。上游 [WinGet ZIP 布局](https://github.com/openai/codex/blob/rust-v0.166.0/scripts/build_winget_package.py)携带两组相同沙箱助手；已核对 [沙箱助手查找](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/windows-sandbox-rs/src/helper_materialization.rs)优先使用主 EXE 同目录文件，因此保留根目录一组，省去这两份资源副本。默认 unelevated 不使用它们，但 TUI 的 `/elevate-sandbox` 仍可达，缺件会回退按文件名查找；保留根助手可避免缺件及宿主回退。提权初始化须另行明确授权。另须分别核对 [Host / 搜索程序查找](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/install-context/src/lib.rs)，不可套用助手规则。当前六个运行文件（不含可选独立执行器）以运行清单为准；源码与摘要检查不代替 Windows 运行验证。

## 其他工具安装与更新

1. 下载到本次包内临时目录，验证来源、架构、版本、依赖和摘要，再解压到表中的相对位置。需要安装器的工具应先确认受支持的便携部署方式，不改宿主 PATH 或注册全局安装。
2. 保留必要 DLL、资源和许可证。可选工具缺失时明确报告，不通过宿主同名程序或旧包路径补齐。
3. 每次更新同时检查对应变量、路径与调用参数。例如 Android 的 `ANDROID_HOME` / `ANDROID_SDK_ROOT` 指向 SDK，`ANDROID_SDK_HOME` 是旧工具用户根；不能因名称相近互相替代。
4. 运行该工具的版本检查和一个有代表性的包内任务，检查输出、临时目录及退出清理；修正本文件、相关 Skill/Plugin 说明和开发记录。

Office/PDF helper 从自身脚本布局定位包根，拒绝旧根环境变量、越界路径和链接。MuMu 使用独立 ADB；APK Lab 的 SDK 检查使用 `tool\android\sdk`。这些边界在补齐工具后仍须保留。

### Office、PDF 与 Android 的依赖边界

Office 已有 python-docx、python-pptx、openpyxl、pandas、Pillow、lxml 和 defusedxml；保留现有成熟工作流，不因换技能而重装同类工具。JS `docx` / `pptxgenjs`、LibreOffice、Pandoc、Poppler 尚未预置；选择相应路径前检查实际依赖。OpenAI templates 缓存保留作为按需选取的模板资料，用户模板优先，不默认激活全部模板技能。

大量 PDF 使用 `home\skills\pdf-library\scripts\pdf_library.py` 的 `build/search/read/verify/export`，具体任务参数见该技能入口。当前已具备文字层提取与索引；OCR 需另行准备包内 Tesseract 和对应 `tessdata`。严格模式发现未处理 OCR、低置信度或内容检查失败时返回 2；不得把文字层检查通过写成图片、布局全部无损。

Appium 采用包内 `tool\automation\appium` 的固定版本 npm 项目和该目录内专用 `APPIUM_HOME`，禁止 `npm -g`、系统 SDK/JDK 或宿主缓存回退。UiAutomator2 首次连接会向模拟器安装 helper APK，这属于设备状态变更，实际测试前必须纳入用户授权范围。当前只评估并整理技能，没有安装 Appium、连接设备或运行 ADB。APK 的可选静态 MCP 使用 `.mcp.manual.json` 和 `-TaskAuthorized` 手动入口，技能发现不会启动服务。

### Node / npm 的项目边界

保留官方 Node 二进制和 npm CLI，六个 npm/npx 启动入口统一调用便携包装器；不回退宿主 Node 或全局 npm。当前工作目录、显式 `--prefix`、npm 配置与缓存路径必须位于包内。默认项目根固定为当前目录，因此不会向上读取宿主父项目的 `.npmrc`；包内 monorepo 需要显式选定其根目录。升级 Node/npm 时保留并复验这些入口和真实配置加载回归，不能用上游默认 shim 覆盖便携约束。

### 一套浏览器：安装、启动与更新

选择 Playwright 是为了复用 DOM 定位、自动等待、控制台/网络、截图和同一 Chromium 的 CDP 诊断。已评估 Chrome DevTools MCP，但不再安装第二套 MCP 或浏览器。已知任务优先 `start-browser.ps1 -TaskAuthorized -TaskScript <包内.cjs>`，免注册 MCP且不遗留 CLI 后台会话；探索任务才使用该入口的前台 stdio MCP 模式，具体示例见 `browser-debug` 技能。

在已由 BAT 初始化的 Windows 终端，从包根执行：

```powershell
.\tool\automation\install-browser.ps1 -Check
.\tool\automation\install-browser.ps1 -Install
.\tool\automation\start-browser.ps1 -Check
```

安装只使用官方固定版本与包内缓存，不启动浏览器、不回退宿主。用户已有包内 Chrome for Testing 可通过 `-ExecutablePath` 指定，但必须另验兼容；免 ChromeDriver 不等于任意浏览器版本都兼容。框架更新时共同核对 `package.json`、`package-lock.json`、上游 `browsers.json`、`versions.json`、文件摘要和手动下载工作流版本；使用包内 npm、`npm ci --ignore-scripts --bin-links=false`，不运行全局安装或上游系统依赖安装器。

浏览器资料固定在包内 `cache/browser`：`profile` 保存 Cookies/网站登录等资料，`cache`、`crashes`、`downloads`、`runtime` 保存对应缓存与进程状态。任务退出关闭本次进程并保留资料，下一次任务复用；不加载日常 Chrome profile。通过根“清理缓存”统一删除这些数据，网站届时需重新登录；运行期间持有独立互斥锁，拒绝并行打开或清理。旧 `-KeepSessionData` 参数保留兼容，不再改变默认行为。下载默认禁止，明确导出的截图和报告保留在所选 `work` 子目录。任务脚本默认 120 秒，可通过 `-TaskTimeoutSec` 在 1–1800 秒内调整。代码入口服从本次任务和执行器权限，不将其描述为运行不可信 Node 代码的沙箱。

`desktop.ps1` 使用 Windows 内置 UI Automation，无额外 Python/Windows-MCP 依赖。仅支持指定 PID 的有界控件树及明确的 Invoke/SetValue；Windows-MCP 的通用 Shell、文件和注册表能力未接入。安装位置、进程重定向和 UI 操作授权是不同边界，不能借此扩大目标应用范围。

### Python 依赖与命令入口

默认保留 Python 爬虫、数据处理、Office/PDF 和日常开发调试依赖；`python-packages.in.txt` 现固定 42 个直接及传递依赖版本。按用户授权，从历史提交 `fcaf45e5dfe4c97f096475f211a423b6d882c4ae` 恢复 PyInstaller 6.21.0、pyinstaller-hooks-contrib 2026.6、altgraph 0.17.5、pefile 2024.8.26、pywin32-ctypes 0.2.3、setuptools 82.0.1，并保留现有 packaging 26.2。恢复的是历史 Git 对象而不是新下载的 wheel；许可证及 Windows x64 bootloader 随组件保留，历史 `__pycache__` 不恢复。Go、uv 仍不包含，不自动补装 `markitdown[all]` 等整套可选依赖。

AI 执行明确的 Python 打包任务时，直接调用当前包内 `tool\python\python.exe -m PyInstaller`，无需额外专用 BAT/CMD 或包装脚本。沿用当前便携会话的隔离环境，显式将 `--workpath`、`--specpath` 放在包内 `tmp` 的本次任务目录，将 `--distpath` 放在包内 `work`，并将 `PYINSTALLER_CONFIG_DIR` 指向包内 `cache/pyinstaller`；不要运行带旧解释器绝对路径的 vendor EXE；该 vendor bin 不加入默认 PATH，已有受管理 CMD 入口继续使用。已有 spec/hook 是可执行代码，须检查其自定义路径且仅运行可信代码；原生模块不是沙箱。仅检查 `--version` 不代表实际 EXE 冻结构建通过。输入清单变更后旧锁摘要不再匹配，不伪造历史 wheel SHA；依赖锁仍从真实官方 wheel 报告生成。

`setup-tools.ps1` 使用已有包内 Python/pip 和 helper，负责当前固定运行集的补装、同版修复。先退出主程序，使用已由 BAT 初始化的 Windows 终端运行；它检查完整路径祖先并取得包独占锁，不在活动会话中替换依赖。直接启动 PowerShell 仍可能在脚本接管前使用宿主缓存。

- 首次以官方 PyPI 为源进行 wheel-only 解析；`python-lock.py` 验证报告中的官方 wheel URL、版本和 SHA-256，再用 `--require-hashes` 安装。禁止源码构建，缓存、目标和临时文件均在包内；`PIP_CONFIG_FILE=nul` 配合 isolated 模式避免读取宿主 pip 配置。
- 安装前拒绝重复或不同版本的已装元数据、默认集以外的发行包及无法归属的 CLI 入口，避免 pip 覆盖安装留下旧元数据或删除后来添加的入口。遇到这些情况保留现状，不靠删除旧锁强行重装。
- 安装、刷新 CLI shim 和导入验证成功后，才发布 `python-packages.lock.txt`；以后按锁安装。输入清单摘要不一致时拒绝旧锁。跨版本升级或扩展默认集须另在包内受控暂存副本安装并验收，核对旧元数据和入口后再替换；此脚本不提供任意原地升级或完整事务回滚。
- `refresh-python-cli-shims.py` 刷新 `tool\bin` 中受管理的 Python CMD 入口，避免旧机器绝对路径；它不能恢复缺失的解释器。
- `optional-python-manifest.json` 保留完整官方 wheel 摘要及 149 个运行/许可证等文件摘要。四个 `dist-info/RECORD` 会被安装器重写，明确排除其安装后字节摘要；不因此修改或豁免运行代码校验。

此前的 36 项运行集已完成官方 PyPI Windows x64 / Python 3.14 wheel 解析、候选锁生成和校验；本次新增的 6 项打包依赖仅从历史 Git 对象恢复，尚未重新进行 wheel 解析或 Windows 安装、导入和打包验收。

缓存、临时文件、生成配置和已登记的 CMD shim 可按各自条件重建；工具 payload、Skills/Plugins、认证和恢复标记不可当作缓存删除。

## 正式版打包与发布

先提交并推送已验证的修改。构建端需要 Python 3.11+、Git 和完整水合的 LFS 工件；不要求在最终用户的便携包中另装 Git。运行：

```powershell
python -B tool/package-release.py --check
python -B tool/package-release.py --version v0.166.0-portable.1
```

目前已发布 `v0.166.0-portable.1`。同版本的新包必须递增便携修订号，不能覆盖现有 Release、标签或下载附件。构建程序会检查所给发行标签与 `runtime-manifest.json` 中实际 Codex 版本是否相同。
