## 03 工具维护：只需选择一个操作（SSH 已合并）

GitHub Actions **03 - 工具维护** 只有一个 `operation` 下拉框，提供三个选项：`diagnose`（故障诊断）、`check`（检查安装，默认）、`update`（一键受控 Tool 更新）。不再设置 `mode / group / create_pr`，也不用单独选择 SSH；工具更新时 SSH/Paramiko 和六项原生依赖包含在完整审核计划中。

- `diagnose`：先运行 Ubuntu 低成本离线/官方元数据诊断，成功后执行隔离 Windows 原生诊断。仅查故障，不修改源码或发布。
- `check`：检查 Windows 包内已安装工具、上游元数据和 SSH 状态；只读，不下载大型候选或创建 PR。
- `update`：首先由只读 Ubuntu Job 核对 Node.js（限已验证主版本内）、ripgrep、fd、jq 的官方稳定版 SHA-256，同时将当前工具版本与已审核的**完整工具锁版本计划**对比。如果只有 Node/CLI 可安全自动更新，执行该候选的原生 Windows 全量门禁；如果已审核的 Python/SSH/Paramiko/npm/Corepack/Playwright/Chromium/7-Zip 等完整计划确有版本变化，则使用完整工具 Windows 门禁。若两个计划同时要求更新，工作流明确失败，需先把候选合并成一个审核批次，**不能悄悄漏掉某一类工具**。没有可执行新版本时停止，不启动 Windows；全部验收成功才由独立受限写入器准备候选分支/PR，仍需人工合并，绝不自动创建 Release。

**自动化边界：** 目前不是“所有 Tool 自动追任意上游最新版”：Python、SSH、npm、浏览器与其依赖需要重新审核官方 SHA-256、ABI、锁版本和兼容回归才能改变完整计划。已安装工具清单与固定版本计划都匹配时，表示**当前已审核批次没有更新**，不代表未支持的上游工具没有发布更新。Node-only 更新会保留单独审核的 npm 12 和 Corepack 目录；不执行系统安装器，不覆盖已验证的跨工具版本。

**GitHub 仓库设置注意：** 如果 GitHub Actions 被禁止创建 PR，Windows 验证和候选分支推送仍可成功，但 PR 创建会被 GitHub 拒绝。需由具有权限的账户在 Settings → Actions → General → Workflow permissions 中开启允许 Actions 创建 PR，或沿用 GitHub Connector 从已验证候选分支建立 PR；无须再次运行昂贵的 AC。

[03 - 检查与准备便携工具更新](https://github.com/rileyaaa/Codex-Portable/actions/workflows/03-update-tools.yml) 只允许人工 `workflow_dispatch`，不响应 push、PR、schedule 或其他 workflow；每次运行消耗 GitHub Actions 额度，**不会由维护代码自动运行**。Windows x64 Runner 负责执行实际兼容回归；用户 Win11 还应在下载最终包后单独试用。

- **常规使用：** 直接在 03 选 `diagnose / check / update` 中的一项；无需 SSH 开关或 PR 勾选。`update` 只在完成所有审核、原生 Windows 测试、19 项 PowerShell 回归、十轮审计、真实 ZIP SHA-256 后准备候选分支/PR，不会立即更新 `main`。

## 正式版打包与发布

正式升级先运行 01，输入 `release_url` 并按稳定性决定是否显式提交；然后在新 `main` 手动打开 [Release 工作流](https://github.com/rileyaaa/Codex-Portable/actions/workflows/02-verify-and-publish-portable.yml)，填写与运行清单匹配的 `version`。默认 `publish_release=false` 执行完整 Windows 检查、十轮回归及实际 ZIP 试打包（验证校验值后删除临时 ZIP，不上传、不发布）；仅经确认后设置 `publish_release=true`，才让独立发布 Job 重建出与测试 SHA-256 一致的 ZIP、上传 ZIP/来源清单/SHA256SUMS 并执行远端附件回读验证。

```powershell
python -B tool/package-release.py --check
python -B tool/package-release.py --version v0.166.0-portable.1
```

独立打包器同时强制校验正式标签与 `tool/runtime-manifest.json` 的固定 Codex 版本一致，未填写 `--version` 时默认使用当前运行版本的 `.1` 修订号；两个正式工作流均会运行校验官方 SHA-256 的固定 `actionlint`。01 在允许提交的稳定版路径上先进行与 02 一致的 18 项 Windows PowerShell 回归，初始 Git 候选只在只读 Runner 本地提交，不会提前推送 `main`。
