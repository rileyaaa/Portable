# 工具安装、恢复与可用性说明

本文件只说明 Codex Portable 的工具体系。项目怎么启动、认证如何迁移见根 [README.md](../README.md)；历史演进见根 [CHANGELOG.md](../CHANGELOG.md)。所有工具必须使用当前包内的路径，不应因为系统 PATH 恰好存在同名程序就被视为已安装。

## 分类与当前状态

| 分类 | 内容 | 当前处理 |
|---|---|---|
| REQUIRED runtime | `codex.exe`、`codex-code-mode-host.exe`、`run-codex.ps1`、`env.ps1`、Windows PowerShell 5.1、`tool\portable-process.ps1` | 基础启动不可缺。主 EXE 与 Host 是同一 0.156.1 runtime pair，缺一个或身份不符即 fail closed。 |
| REQUIRED for account_json/proxy | `login-json.ps1`、`login-json-http.py`、`tool\python\python.exe`、`tool\socks-http-bridge.py` | API/browser 基础启动不必一定走 Python，但 account JSON HTTP backend 和 SOCKS-to-HTTP bridge 需要它；Minimal 保留。 |
| BUNDLED full-package tooling | `tool\bin` 的 7-Zip、rg、fd、jq、uv/uvx；`tool\python`；`tool\node`；`tool\go` | 完整包保留。工具是否可用以实际文件为准，不能把 PATH 预留项当作可用。 |
| OPTIONAL / currently not present | Git、Android SDK/JDK/adb/JADX/dex2jar/apktool/Maestro、LibreOffice/Pandoc、Poppler/qpdf、FFmpeg、Tesseract、pnpm/Appium 全局工具 | 目录或环境变量可能预留，但当前没有 payload；功能需要时使用完整包和受支持的包内安装/放置流程。 |
| DEV/TEST-only | `project-regression-r19.*`、`security-selftest.py`、`updater-runtime-pair-selftest.ps1`、测试 fixture | 仅维护/验证使用，不是普通启动依赖。 |

Clean Portable 不附带开发检查器。Optional 工具与 required runtime 的边界以本表和实际文件为准；PATH 中偶然存在同名程序不等于包内已安装。

## 完整包与 Minimal Runnable 包

完整包适合工具扩展、维护、Node/Go 工作流、Skills 与 Plugins。Minimal Runnable 包只为核心 Portable 场景保留：Codex + Code Mode、正常/维护启动、API/account_json/browser 三种入口、认证切换、Python HTTP/bridge、PowerShell process supervision、runtime identity gate 以及三份权威文档。

Minimal 故意不带 Node、Go、`tool\bin` 的可选 CLI、大型 Skills/Plugins、Android/Office/PDF/media/OCR 工具、测试工具、cache、session、日志或用户凭据。因此 Minimal 不提供下列能力，遇到需求请使用完整包：

- Node/npm、Go、uv/7z/rg/fd/jq 的包内运行保证；
- Android、Appium、APK 静态/动态工具链；
- Office、PDF、OCR、媒体外部程序；
- bundled Skills/Plugins 和其专用工作流；
- 开发回归、自测与 updater 故障注入。

不要把 Optional 工具从系统安装目录加入 PATH 来“补齐” Minimal；这会破坏 Portable 可重复性。应改用完整包或将可证明来源的工具放到约定 package-local 位置后，再确认实际 package-local 路径与版本。

## Runtime pair 维护

当前固定 SHA-256：

- `codex.exe`：`70bcb05f9bf1a4e7306edd0cd1b57d02af3267ad02a34b26f45c8c4bb20a3301`
- `codex-code-mode-host.exe`：`0f83a73dc6d511d43bd3e52cc0a999cb383c19c645ef3fbd8fbdaddde3088138`

正式包只预置根目录这一份 `codex.exe`。`home\.sandbox-bin\codex.exe` 若由运行期生成，不应进入长期发行内容；维护收尾时按大小与 SHA-256 确认完全相同且无静态引用后删除。Python/Node/Go 等第三方 runtime 内的同内容文件可能是依赖布局所需，不按重复哈希单独拆除。

## 安装/更新规则

1. 下载到临时位置，校验来源、版本、架构、签名/哈希（若上游提供）。不要直接运行系统安装器。
2. 使用绿色/zip payload 解压到对应 package-local 路径，保持目录名不变。
3. 不要单独覆盖 `codex.exe` 或 `codex-code-mode-host.exe`。Clean Portable 不附带版本升级工具，也不支持在发行包内原地更新 runtime pair；需要更换时应重新解压经过验证的发行包，或使用完整维护工作树成对恢复。
4. 更新其他 package-local 工具后，只对对应工作流做必要 smoke；不要依赖宿主 PATH 的偶然存在。
5. 不要执行 Node ZIP 随附的 `install_tools.bat`；它可能尝试系统级安装，且本项目会拒绝其出现。

### 固定位置

| 工具族 | package-local 位置 | 注意 |
|---|---|---|
| Python embeddable | `tool\python` | `python3xx._pth` 必须保留 `Lib\site-packages` 和 `import site`；该 runtime 不等同 venv。 |
| Python CLI shim | `tool\bin\*.cmd` | 由 `tool\refresh-python-cli-shims.py` 在明确 setup/refresh 后再生；不能恢复 Python runtime 本身。 |
| uv / uvx / 7z / rg / fd / jq | `tool\bin` | 7-Zip 的 `7z.exe` 与 `7z.dll` 必须成对。 |
| Node/npm | `tool\node` | 使用官方 Windows zip；不使用其系统 installer helper。 |
| Go | `tool\go` | launcher 固定 `GOROOT` 和 `GOTOOLCHAIN=local`，cache 指向包内。 |
| Git | `tool\git\cmd` / `tool\git\bin` | 当前未预置，不回退宿主 Git。 |
| Android | `tool\android\...` | 当前只保留目录结构，JDK/SDK/adb 等并未随包提供。 |

## Python 依赖与可再生内容

`tool\python-packages.in.txt` 是项目 Python 直接依赖清单。`tool\setup-tools.ps1` 是显式维护脚本，不是“自动下载所有工具”的万能修复器：它需要现有包内 Python、uv 与 helper，按锁定/哈希策略安装 Python 依赖，并可刷新受管理的 Python CLI shim。

可再生：运行期目录、缓存、生成的 `home\config.toml`、已登记的 Python CMD shim（前提是 Python 与 generator 仍在）。

不可凭空再生：Codex/Host runtime pair、Python/Node/Go payload、第三方 EXE/DLL、Skills/Plugins 内容、认证 snapshot、installation identity、logout/transition/recovery state。不要把这些当缓存清理。

## 检查与故障排查

```powershell
.\codex.exe --version
```

如果基础 Codex 启动失败，优先确认根 `codex.exe` 与 `codex-code-mode-host.exe` 均存在且同目录，并查看启动器是否报告固定 SHA/runtime identity 不匹配。Clean Portable 不附带 checker/updater；runtime pair 缺失或不匹配时，请重新解压经过验证的发行包，或在完整维护工作树中恢复匹配 pair。若可选工具缺失，先确认对应 package-local payload 是否实际存在；不要伪造空 EXE、复制未知旧版本或依赖全局 PATH。

## 0.156.1 配置核对

`CODEX_*` 中的认证、代理、模型、思考与 Fast 开关主要是 `env.ps1`/`run-codex.ps1` 的便携配置接口，不等同于 Codex 原生环境变量。真正传给 Codex 的相应 `config.toml` 键仍需在 Windows 运行时核验。Node、Go、Android、Office 等第三方环境变量保留为包内路径；是否能用取决于对应 payload。0.155.0 起官方导出的 bundled model catalog 不再提供 base instructions，手工强制为未知第三方模型生成兼容 catalog 的路径需要在新版 EXE 上实测；默认 auto 路径不生成此目录。若使用该少见场景，先不要把测试结论视作已通过。
